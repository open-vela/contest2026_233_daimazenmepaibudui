# kws_tpl_gen —— 在 PC 上生成唤醒词出厂模板

给板子的唤醒词「**你好，openvela**」做模板（`slot0.tpl`），随固件打包进 ROMFS。

## 为什么要在 PC 上做

板子上录模板的唯一入口是 `hw_test kws enroll`，但那**要麦克风**，而 hello_app
常开麦一直占着（`audio_in_start()` 的软占用锁直接 `-EBUSY`），且按 2026-09-19
的决定 hello_app **设计上停不下来**（不注册 SIGINT/SIGTERM，`g_running` 没有任何
代码清它，`sifli_ap.c` 还有看护线程会把它重新拉起来）。所以 `enroll / test /
live` 全过不去。

而 `kws_dtw.h` 本来就写明模板有两条来源，其中 **(a) 出厂模板**是随固件打包、
开机 `kws_init()` 自动补装的，压根不需要板子的麦。本工具就是把 (a) 在 PC 上跑通：
把 `app/hello_app/kws_dtw.c` **原样**编到 x86，跑的就是板上那一份 `kws_enroll()` ——
特征口径、文件格式、校验和是同一份代码。

## 文件

| 文件 | 作用 |
|---|---|
| `kws_tpl_gen.c` | 生成器：读 WAV → `kws_enroll()` → `slotN.tpl` |
| `build.sh` | 编译（不复制不改写 `kws_dtw`，直接编 `app/hello_app/kws_dtw.c`） |
| `selftest.py` | 自检：正例 + 两层负例 + 头字段/校验和核对 |
| `kws_dist.c` | **量距离**：一段录音到某条模板的 DTW 距离 —— 标定阈值用（见「实测」） |
| `rec_check.sh` | **录之前先跑**：录 2 秒量电平，告诉你麦到底有没有声音 |
| `nuttx/config.h` | 空壳，只为让 `kws_dtw.h` 的 `#include <nuttx/config.h>` 编得过 |

## 录之前先验麦

```bash
./rec_check.sh        # 录 2 秒，当场报峰值
```

判据：**峰值 ≥ 3000（约 9%）才算有声音**。峰值 ≤ 300 就是麦没接上 ——
别重录，先解决输入。2026-10-30 踩过：用户照着录了 4 秒，格式/时长全对，
但整段纯静音（峰值 1），而 ALSA 那边 Capture 是 100% 未静音 —— 问题在
**VMware 虚拟声卡压根没接麦克风**，guest 里怎么调都没用。

## 录音要求

**不满足会直接失败，看工具打印的那行。**

- **16 kHz / 单声道 / 16 bit** —— 这三条是 `kws_dtw` 的固定口径，写进模板头校验
- 一句完整短语，**前后各留 0.3~0.5 秒安静**（端点检测靠它起停）
- 有效语音 **≤ 2.0 秒**（`KWS_MAX_FEAT = 100 点 × 20ms`）
  「你好，openvela」正常念是 1.5~2.0 秒，**念太慢会被截成残模板**
- 用**准备在板子上对着说话的那个位置/距离**录最好

录的方法（任选）：

```bash
# ① Linux 直接录（VMware 里要先把麦克风透传给虚拟机）
arecord -f S16_LE -r 16000 -c 1 -d 4 /tmp/hello.wav
#    念「你好，openvela」，念完等一两秒再 Ctrl+C

# ② 手机录了传过来再转（手机 App 一般出 m4a/mp3）
ffmpeg -i 手机录音.m4a -ac 1 -ar 16000 -sample_fmt s16 /tmp/hello.wav
```

⚠ 你终端粘贴有乱码前科：命令粘完先看一眼屏幕上的字再回车。

## 生成

```bash
cd tools/kws_tpl_gen
./build.sh
./kws_tpl_gen -o out /tmp/hello.wav                # → out/kws_out/slot0.tpl
./kws_tpl_gen -o out 你好.wav Hello.wav            # → slot0 + slot1
python3 selftest.py                                # 先自检
```

- `-o` 输出目录（必须已存在）
- `-p` 前后各补多少毫秒纯静音，默认 300；录音本来就带静音可给 `-p 0`

`slot0` =「你好，openvela」，`slot1` =「Hello，openvela」（`kws_dtw.h` 定的语义）。

## 判据（串口）

| 看到什么 | 意味着 |
|---|---|
| `[KWS] 出厂模板补装到 /data/kws：N 字节（M 条）` | 模板从 ROMFS 装进去了 |
| `[KWS] 唤醒词就绪：2 条模板（词：你好，openvela / Hello，openvela）` | **装上了，链路开起来了** |
| `[KWS] 没有模板…` | 没装上 —— 检查 ROMFS 有没有重生成 |
| `[KWS] 模板载入：0/4 条可用` | 文件在但被拒（版本/口径/校验和不符），看它上面那行报错 |

装上之后对板子说「你好，openvela」，看串口有没有唤醒命中。

## 诚实预期：阈值没在这一步定

`kws_dtw.h` 里实测（合成信号）：类内距离 620~660、类外 2450~3100，默认阈值 1800。
但**同音节换序的负例能压到 1806** —— margin 比看起来小。所以：

- 换说话人/换口音（目标用户是老人、可能说冀鲁官话）**必须上板实测类内距离**
- 想要余量可试 **1100~1300**
- **绝不能超过 9000** —— 距离被 DTW 的 DP 上限钉住，超了等于任何输入都命中

命中率不够就多录几条同一句话（`KWS_MAX_TEMPLATES = 4`），别一上来就动阈值。

## 实测（2026-10-30，`kws_dist`，用户手机录的那一条）

工具：`./kws_dist --dir <输出目录> 被测.wav ...`。量的就是板上同一条
`kws_distance_pcm()`，同口径。

**类内** —— 同一句话做扰动（23 个变体）：

| 扰动 | 距离 | 说明 |
|---|---|---|
| 原样 | **0** | 同一份录音，等于 `distance0`（顺带验了工具没跑偏） |
| 音量 ×0.5 / 0.3 / 0.2 | 168 / 383 / 474 | **几乎不要钱** —— 端点检测 + CMN 在扛 |
| 前后静音 20ms / 800ms | 0 / 0 | **完全不要钱** |
| 带宽削（闷/薄） | 433 ~ 716 | 廉价麦、远场 |
| 说快说慢 ±18% | 727 ~ 1104 | 换口气、换节奏 |
| 加噪 30/20/15 dB | 788 / 1018 / 1125 | |
| 削顶失真 | 643 / 1084 | 增益开太大 |
| 组合（轻声+噪 / 变速+噪 / 削顶+大声+噪） | 1049 / 1228 / **1650** | 最坏的一个 |

**类外** —— 「不是这句话」（7 个可比的）：

| 负例 | 距离 | |
|---|---|---|
| 丢掉中间一段 | **1265** | ✗ **误命中** |
| 相邻两段对调 | **1579** | ✗ **误命中**（头注释说的那条，复现了） |
| 同一句话 ×4 | 1835 | ✓ |
| 纯单音 330Hz | 1930 | ✓ |
| 纯噪声 | 1939 | ✓ |
| 六段随机打乱 | 2440 | ✓ |
| 整段倒放 | 2554 | ✓ |
| 只说前半 / 前 1/3 / 纯静音 / 哔哔声 | **没比成**（太短或超带宽） | ✓（另一种不命中） |

⚠ **这些负例都是从同一段录音切出来的**，音色跟模板同源 —— 量出来的是
**类外下界**，真实换人/换句子只会更远。按最坏情况读。

### 结论：类内最坏 1650 与类外最好 1265 **重叠了**

**没有一个阈值能同时把两边分开。**

| 阈值 | 类内召回 | 类外误命中 |
|---|---|---|
| **1800（现值）** | 21/21 | 2/7（丢中间段、相邻对调） |
| **1250** | 20/21（只丢那个「削顶+大声+噪」的 1650） | **0/7** |

**但先别动 1800。** 理由：

1. **误命中不致命，漏命中才致命。** KWS 是**并行触发器不是闸门**（见
   `kws_dtw.h`）—— 误命中只是让板子多收一句没用的话送去大模型；漏命中是
   这个功能直接就没了。按「稳定性优先 / 别又不能对话了」的排序，先保召回。
2. **类内是用合成扰动估的**，真人（尤其老人、冀鲁官话）的类内分布几乎肯定
   更宽，可能本来就会超过 1250。拿单人单句的扰动去收紧阈值，等于赌真人分布
   不散 —— 不划算。
3. 真正该做的是**上板量真人类内距离**（命中会打印 `距离 N`）。等有 10 次真人
   命中的 N 值分布，再定阈值，那才是有依据的。

**看到误唤醒再收**，收多少按实测的误唤醒距离来定，别按上面这张表猜。

## ★ 上板实测（2026-10-30 晚，真机）—— **上面那套合成估计是错的**

对板子说 8 遍「你好，openvela」，同时板子还说了 15 句别的话（问天气、闲聊）。

**真人类内（板子麦，n=8）**：

```
1397  1410  1446  1472  1495  1511  1533  1548
min 1397   中位 1495   均值 1476   max 1548   极差只有 151
```

**真实类外（n=15 句别的内容）**：**全部 > 1800**，一个都没误命中。
→ 误唤醒率 **0 / 23** 个有效语音段。

### ⚠ 现实与预期不符：真人类内是合成估计的 **2 倍**

| | 合成扰动估的 | 真机实测 |
|---|---|---|
| 轻微变化（音量/静音长短/带宽） | 0 ~ 700 | **不在这个量级** |
| 典型 | 400 ~ 1250 | **1397 ~ 1548** |
| 最坏 | 1650 | 1548 |

**如果按上面那张表收到 1250，这 8 次真机命中会全部漏掉。**
合成扰动（同一段录音做增益/加噪/变速）**严重低估**了真实发音的变化 ——
真人每次张嘴的音素边界、能量包络、声道都不一样，这些变化重采样模拟不出来。
**教训：合成数据只能用来发现"哪里会坏"，不能用来定阈值。**

### 阈值 1800 是对的，但余量偏薄

| | 距离 |
|---|---|
| 真人类内 max | **1548** |
| ↑ 余量 | **252** |
| 阈值（现值） | **1800** |
| ↓ 真人类外 | **> 1800**（只知道超了，不知道超多少） |

**就保持 1800，先别动。** 8/8 命中、0/23 误唤醒，是实测跑出来的，不是估的。
它正好卡在两堆实测数据中间。要动就等出现真漏命中 / 真误唤醒再按实数动。

**还想再稳一点**（可选）：现在唯一的模糊地带是"真人类外到底多远" ——
板子只有命中才打日志，近失是静默的，所以那 15 句的**具体距离拿不到**。
要拿到得给 `kws_match()` 加一行"未命中也报距离"（见下）。

## 近失打日志（要标定阈值就得有它）

`kws_match()`（`app/hello_app/kws_dtw.c:724`）现在只在 `best <= g_threshold`
时 printf，miss 静默 `return 0`。**后果是"喊了没反应"连差多远都查不到。**

改动是一行，且**不刷屏** —— `kws_match()` 只在句子收口时跑（`kws_finish_utterance()`
里调），一次一个语音段，不是每帧：

```c
  if (best <= g_threshold)
    {
      printf("[KWS] 命中唤醒词（slot%d，距离 %d ≤ 阈值 %d）\n", ...);
      return 1;
    }

  /* 近失也要留痕：否则"喊了没反应"连差多远都不知道，阈值没法标定 */
  printf("[KWS] 未命中（距离 %d > 阈值 %d）\n", best, g_threshold);
  return 0;
```

有了它，说几句别的话就能读出真实类外距离，两堆实数中间的空隙才量得出来。
**没做** —— 要重新编译烧录，等你说了算。
