# 验收与测试

> 每个用例都写"怎么做 → 看什么判据"。串口采集见
> [BUILD_AND_FLASH.md §7](BUILD_AND_FLASH.md#7-串口采集)。
> 报警测试会真的给家人发 Bark，测之前先确认。

## 0. 前置检查

| 项 | 判据 |
|---|---|
| 串口 | `[版本]` 标记是当前版本；`[信标] up=… sm=…` 持续在走 |
| 网络 | PC `ping -c 2 192.168.137.2` 通；串口有 `[netmgr] Network connected` |
| 对时 | 串口出现 `[TimeSync] 已对时 -> …`；屏幕顶栏是本地时间 |
| 凭据 | 没有 `HTTP 403` / `quota exhausted` / `TTS 首句合成失败` |

## 1. 语音问答（正常路径）

**操作**：说「你好，给我讲个小故事」。
**判据**：

```
[VAD] 检测到语音开始 / 语音结束
[AI] 识别结果: …
[LLM] AI回复: …                      （或 [LLM] 直连兜底成功）
[volc_tts] TTS V3 request: …        （火山 TTS 接管）
[volc_tts] TTS: synthesized … PCM bytes
[TTS] 首字开始播放
```

- 回复应 ≤ 约 160 字、两三句；
- 听不到应看：`[TTS] 首句合成失败`、`HTTP 403`、`降级到火山引擎`、`播放设备` 相关行。
- 延迟基线：ASR 约 8~11 秒 + LLM 约 7~10 秒 + TTS 首块约 2~5 秒。


## 1.1 自我介绍（本地快路）

**操作**：说「你能做什么」「你会什么」「你是谁」。
**判据**：

```
[自介快路] 命中「你能做什么」-> 直接念固定模板
```

- 回复必须是用户指定的模板，一字不改：
  「我是智爱助手，可以和您聊天，答时间，查天气，设提醒，紧急响铃联系家人，
  上网搜索消息，还能修改音量和亮度，有什么需要帮忙的的和我说。」
- ⚠ 这条依赖 **ASR 把关键词转出来**。真机出现过只转出「你好你好」、
  问题后半句丢了 → 模型按问候回答，快路也不会触发；这不是模板丢了。

## 2. 天气（快速通道）

**操作**：说「济南天气怎么样」。
**判据**：

```
[天气快路] 城市=济南，直接查 Open-Meteo（跳过 velaclaw/LLM）
[mimo_voice] 天气: 济南 lat=… lon=…
[天气快路] 回复：济南：… 气温 … 度 …
```

- 首字出声应 ≤ 约 20 秒（原来走 velaclaw 要 105 秒）；
- **不应**出现 `-110`、`轮 2 卡在 LLM 相位`；
- 说一个不认识的城市的天气 → 日志 `[天气快路] 不认识的城市的说法…回落到大模型`，
  此时允许走原路径（慢但正确）；
- 默认城市是济南（`MIMO_DEFAULT_CITY`）。

## 2.1 实时信息（Tavily 原话检索）

**操作**：说「今天有什么新闻」或「最近有什么最新消息」。

**判据**：

```
[AI] 识别结果: …新闻…
[实时] Tavily 查询：今天有什么新闻
[web_search] Tavily OK: N bytes
[实时] 取到结果，直接念（Tavily 优先 / 新浪兜底，跳过 LLM 汇总）：1. …
[volc_tts] TTS V3 request
```

- 查询就是**用户原话**（只去掉 ASR 常带的开头「你好，」），不再按娱乐/体育/财经分类；
- 先走通用 `web_search`（Tavily），没结果再退 `news_search`（新浪免 key 兜底）；
- 最多念 3 条：标题（去掉 ` | 来源` 后缀）+ 第一段正文；版权/页脚/导航行会被过滤；
- 输出缓冲 12 KB，串口应看到 `Tavily OK:` 字节数**大于 1024**（旧版 1024 字节上限会把 10 条截成 1 条）；
- 已取消「第X条详细说说」专门路径，后续追问交给大模型。

## 3. 语音急救（关键词）

**操作**：喊「救命」/「报警」/「着火了」。
**判据**：

```
[急救词] 命中「救命」-> 走报警
[急救] 触发：…
[急救] 响铃开始：10 秒内说「没事」就停，否则通知家人
```

- 不需要唤醒词；会话闸门锁着也必须报警；
- **请清楚地说「救命」**：真机 10.3 秒的嘶吼 ASR 返回空（后面跟两次
  「没听清楚」），关键词逻辑根本没机会跑。AI 的 ASR 对持续嘶吼不如正常说话稳。

## 4. 说「没事」取消

**操作**：报警铃响后，等铃停下来的空档说「没事」，**手不要碰屏幕，等 8 秒**。
**判据**：

```
[急救] 听窗内收到人声 -> 开麦收「没事」
[AI] 识别结果: 没事
[急救] 老人说没事 -> 停铃，**不通知家人**
```

- 听窗放宽到 2.8 秒（确认期）；ASR 往返可能需要几秒，别急着点按钮；
- 若失败，看 `[急救] #N 听 …（录音链路 死的/活着，这一窗有没有音频流过）`
  和 `[监听守护] 录音线程卡在设备读里` —— 录音链路问题见 TROUBLESHOOTING。

## 5. 本地撞击求救（连敲两下）

**操作**：15 秒内敲桌子/拍手 **两下**；只敲一下**不该**报警。
**判据**：

```
[门控] 第一次撞击（fall/knock 0.xx），先不报警；15 秒内再来一次才报
[门控] 15 秒内第二次撞击（间隔 xxxx ms，fall/knock 0.xx）-> 确认求救，进入报警
```

- **fall 和 knock 都算"撞击"**：真机连敲时模型 top1 常是 `fall 0.57`，
  不是 knock；只认 knock 会"敲了没反应"；
- 单次置信度 **≥0.80** 直接报警（非常像的真事件）；0.55~0.80 的单次只记时间；
- 模型侧 fall/knock 不应期都降到 2 秒，连敲两下能各自出一次命中；
- 日志：`[小模型] 判据 fall/knock：…（阈值 0.55）`。

## 6. 摔倒/持续噪声

**操作**：安静环境下不要制造持续噪声（风扇/摩擦），观察 1 分钟。
**判据**：

- 不应出现 `★命中 fall/knock` 直接报警；**连续 >6 秒**的持续声才被
  `⚠声音还在持续（未回落），先不报` 挡住（短敲几窗不受影响）；
- 撞击判据：单次 0.55~0.80 不报，两次（15 秒内）才报，单次 ≥0.80 直接报；
- 人声窗/人声余温只允许 scream，不会走撞击；
- 真摔倒的验证需要真机事件，当前以日志分布为准。

## 7. 报警通知（Bark）与 3 分钟时长

**操作**：让一次报警过 10 秒不说「没事」（确认会给家人发消息）。
**判据**：

```
[急救] 10 秒没人说没事 -> 通知家人，铃继续响
[PUSH] OK: HTTP 200 -> https://api.day.app/push
[急救] 再发一次通知                  （30 秒后，重复到 180 秒）
[急救] 180 秒到点，自动收摊
```

- 手机应收到 6 条左右（10/40/70/100/130/160 秒）；
- 收不到但串口是 HTTP 200 → 检查 Bark device key / 手机端配置。

## 8. 屏幕与状态

- 主屏顶栏时钟每 10 秒刷新（UTC+8）；
- 报警页/确认页出现后，取消或到点应撤页回主屏（`ui_post_panel(2)`）；
- AI 播报时屏幕文字随音频逐句推进（看 `[Bridge] AI 回复已上屏: …` 的前缀在变长）。

## 8.1 屏幕镜像与虚拟触摸（lcd_mirror）

用途：本板屏幕玻璃损坏、FT6146 触摸 IC 偶发不应答，PC 镜像用来实时看屏
并用鼠标操作界面；触摸恢复前它是唯一可操作通道，也用于演示、录屏和截图。

板端（默认 autostart，目标 192.168.137.1:5600）：

```text
hw_test lcdmirror status                 # 看传输方式/目标/已发帧/触摸事件
hw_test lcdmirror stop / start           # 停/起（停掉连鼠标注入一起停）
hw_test lcdmirror start 192.168.137.1 5600
hw_test lcdmirror uart [dev]             # 切控制台串口（默认 /dev/console）
hw_test lcdmirror tcp <ip> [port]        # 切回 TCP
hw_test lcdtap <x> <y> <0|1>             # 串口模式下手动注入触摸
```

PC 端（Windows，Python 3.10 + Pillow；串口模式再加 pyserial）：

```bash
py -3.10 tools/lcd_mirror/lcd_mirror.py                 # TCP 5600
py -3.10 tools/lcd_mirror/lcd_mirror.py --scale 1.5     # 放大窗口
py -3.10 tools/lcd_mirror/lcd_mirror.py --serial COM4 --baud 1000000
```

操作：左键按下 = 触摸按下，拖动 = 滑动，松开 = 抬起；空格暂停显示，
`t` 开关计时打印，Esc 退出。窗口 `fps` 应持续 >0，`#seq` 递增；板端
`status` 的触摸事件数应随点击增加。

其他脚本：

- `lcd_mirror_dump.py`：无头收帧，按脏矩形拼成 PNG（截图归档）；
- `mirror_tap.py`：脚本化点击一次（自动化测试）；
- `mirror_latency.py`：量「点一下 → 画面变化」的端到端延迟；
- `lcdmirror_serial_dump.py`：串口模式无头收帧；
- `host_test/`：协议解析、坐标映射、串口重同步的主机侧测试。

判据：

- PC 窗口能看到 390×450 主屏，时钟走字，点击「菜单/设置」板端界面响应；
- 板端 `hw_test lcdmirror status` 显示已连接（TCP 或 UART）、触摸事件递增；
- 拔掉 RNDIS 后 TCP 断开，切 `hw_test lcdmirror uart` + PC `--serial` 仍能看/点。

限制：

- 只镜像走 LVGL 的刷屏；`hw_test lcdcolor` 这类直接写 `/dev/fb0` 的不进镜像；
- 快速变化区域可能撕裂（下一帧自愈）；
- 面板固定 390×450 竖屏（CO5300 不吃 MADCTL，横屏只能软件转置）；
- TCP 依赖 RNDIS；RNDIS 挂死时用串口链路。

## 9. 稳定性回归（建议 30 分钟）

| 观察项 | 正常 | 异常指纹 |
|---|---|---|
| 信标 | `[信标] up=… beat_age<200ms sm=…` 每 10 秒 | 断流/beat_age 持续 >2s |
| 录音守护 | 偶尔 `卡在设备读里` 后 `语音监听已恢复` | 反复 8 秒卡死 + `放弃 join` 连发 |
| UI | `[ui] 慢统计` 每秒，最慢 < 500ms | `lv_timer_handler` 长期 >1s |
| TCP 池 | `[TCP] pool=…/128` 不持续上涨 | `D` 数只涨不跌、`ENOMEM`、`net_connect ret=0x42` |
| 内存 | `free heap` 不单调下降 | 每轮对话掉几百 KB |

## 10. 已知不达标项（截至 2026-11-01）

- 普通问答首字仍需 ~20 秒（ASR/LLM 云端往返，未做 token 级流式）；
- ASR 对长句/方言的延迟与准确率依赖云端；
- 定时提醒是 RAM，掉电丢失；语音删/改提醒未实现；
- 实时信息只做 Tavily 原话检索，结果条数受中文索引限制（约 1~3 条）；
- 音频链路 8 秒卡死已加 owner_gen 修复，仍需长时间真机验证；
- TLS 出站连接堆积已在 NuttX 内核修复（TIME_WAIT 到期补 `tcp_free` + 池满回收
  `TCP_CLOSE_DIRECT` 的 CLOSED 条目），修复已编译，尚需长时间真机回归。
